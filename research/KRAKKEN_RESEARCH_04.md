# Krakken collision experiments and bounds

**Completed against the unchanged original scalar and AVX2 implementations.**

We tested reduced-round H159 hashing at every depth from **one through eight
complete rounds**, found explicit truncated collisions, and replayed the same
messages through the full eight-round hash. **No 256-bit digest collisions
were found in either tested dataset.** This is not a proof of general collision
resistance or a 128-bit attack-work bound.

The principal results are:

- An exact finite-family theorem: the 256-bit digest is injective on one
  explicitly defined **1,048,576-message affine family**, at every tested depth.
  Even the first 48 output bits are injective on this particular family.
- **927 distinct reduced-round 32-bit collision pairs** were replayed at eight
  rounds. None retained its 32-bit collision. Other 32-bit collisions exist
  at eight rounds, as expected for such a short truncation.
- A separate, preserved sample of **262,144 uniform H159 messages** supports
  a simultaneous **99%-confidence collision-probability ceiling of 2^-29**
  for two independent uniform messages, at all eight depths. Equivalently,
  it supports a 29-bit collision-entropy floor for the digest distribution.
  This is a statistical population statement, not 29-bit collision-search
  security and not an adaptive chosen-message bound.

## What exactly was tested

For r=1,...,8, define H_r(m) as the first 32 bytes after applying the first
r original indexed rounds to

```
state bytes 0..158   = the 159-byte message m
state byte 159       = 0x86
state bytes 160..255 = zero
```

At r=8 this is the existing H159 hash interface with a 256-bit output.
The reduced variants retain the original padding, state layout, round
constants, and layer definitions. We did not repeatedly apply round zero.

Three objects must be distinguished:

1. A **full-state permutation collision** would require two distinct
   2,048-bit inputs to have identical 2,048-bit outputs. This cannot happen:
   each original round is bijective, so every tested prefix is bijective.
2. A **digest collision** requires only the extracted 256 bits to agree.
   Such collisions must exist over the full H159 domain, but none was found
   in these tested sets.
3. A **k-bit truncated collision** requires only the first k digest bits to
   agree. All truncation widths here are whole bytes: 24, 32, 40, 48, or 64.
   The discovered examples are of this third kind.

The previous NOTE-006 experiment checked 8,192 messages at eight rounds
and established a stronger pair-XOR property on that much smaller family.
This new experiment examines a larger family at all eight depths and adds
a different, independent-message population collision test. It does not
assert the old pair-XOR uniqueness property for the new million-message set.

## Structured family: exact counts at every round

For x=0,...,2^20-1, define the 159-byte message by

```
m[i] = (37*i + 11) mod 256, for i=0,...,158
m[0] = x & 255
m[1] = (x >> 8) & 255
m[2] = (m[2] & 240) | ((x >> 16) & 15)
```

This exhausts a 20-dimensional affine message family. Each entry below
counts **unordered distinct-message pairs**, not merely occupied buckets.
A bucket of k messages contributes k*(k-1)/2 collision pairs.

| Rounds | 24-bit pairs | 32-bit pairs | 40-bit pairs | 48-bit pairs | 64-bit pairs | Full 256-bit pairs |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 33005 | 141 | 1 | 0 | 0 | 0 |
| 2 | 32939 | 111 | 2 | 0 | 0 | 0 |
| 3 | 33048 | 130 | 1 | 0 | 0 | 0 |
| 4 | 32834 | 113 | 2 | 0 | 0 | 0 |
| 5 | 32910 | 121 | 1 | 0 | 0 | 0 |
| 6 | 32592 | 141 | 0 | 0 | 0 | 0 |
| 7 | 33042 | 127 | 0 | 0 | 0 | 0 |
| 8 | 32864 | 122 | 0 | 0 | 0 | 0 |

For comparison only, an ideal random k-bit map on this many distinct inputs
has expected unordered collision count N*(N-1)/2^(k+1). This is about
32,768 pairs at 24 bits, 128 at 32 bits, and 0.5 at 40 bits per depth.
These benchmarks explain why short-prefix collisions are ordinary outcomes;
they are not a randomness proof for Krakken.

### Exact theorem KRAKKEN-COLL-001

For every r=1,...,8, H_r is injective on the explicitly defined family F.

**Proof certificate:** the first 48 output bits have no repeats after exact
sorting. Equality of two complete 256-bit digests would force equality of
those 48 bits. Therefore every pair of distinct family messages has distinct
digests. Independent C and NumPy counts agree, and a Clang build reproduces
every archived digest generated by GCC.

This covers all **549,755,289,600 unordered distinct-message pairs** per
depth. Sorting proves that statement without explicitly evaluating each pair.
For every nonzero XOR difference confined to the family's 20 free bits,

```
Pr_(M uniform in F)[H_r(M) = H_r(M XOR difference)] = 0.
```

The partner remains in F, so this covers all 2^20-1 nonzero within-family
differences. This is an exact restricted-domain result, not an assertion
about messages outside F or a computational work lower bound.

## An explicit two-round collision candidate, replayed at eight rounds

The following is a **40-bit truncated collision**, not a full-digest collision.
Using the message recipe above:

- Message A has x = **537888**.
- Message B has x = **635755**.

Their complete two-round digests are:

```text
acc761d30e87ea242bbed8ef931bfe6599e72369fafaba67f9f69bcb6b5f030b
acc761d30e9014f1bf878a350d636e69c6a0e91b967bc3dd7b7d5de57bb65970
```

The first five bytes agree: `acc761d30e`. Their complete eight-round digests are:

```text
56568663199563368d5bdd2b589ea346bcd33b0ed040c083ec0577c21950174c
3403ac610090323cb09d55b61fc55a9f096016ce3c9ae608e2faa028d65118d7
```

The eight-round digests differ in **128 of 256 bits**. Their digest Hamming
distances at depths one through eight are `[125,108,127,121,132,117,122,128]`.
The five-byte equality occurs only at round two for this pair.

“Porting” here means hashing the SAME original messages through eight total
rounds, retaining the normal indexed constants. It does not mean appending
eight extra rounds to their reduced-round outputs or altering the messages.

Across both datasets, all 927 distinct pairs selected by a 32-bit collision
at rounds one through seven lost that equality by round eight. The seven
40-bit candidate rows are subsets of those 32-bit pairs and also lose their
collisions. None of the candidate pairs collides on the full digest at any
tested depth. The complete records are in `collision_witnesses.json`.

This is an empirical statement about these selected pairs. It does not prove
that all reduced-round collisions disappear, or that a different structural
collision attack cannot extend to eight rounds.

### KRAKKEN-STAT-002: population collision bound at all eight depths

For independent uniform H159 messages M,M', let

```
C_r = Pr[first64(H_r(M)) = first64(H_r(M'))].
```

The completed no-repeat test supports, **simultaneously for all r=1,...,8,
at confidence at least 99%**,

```
C_r < 2^-29.
```

Consequently the same ceiling applies to full 256-bit digest equality and
to the genuine collision event `M != M' AND H_r(M)=H_r(M')`. The equality
definition includes the tiny probability of sampling the same message twice;
using it only makes the genuine-collision upper bound conservative.

For the full-digest distribution this also supports

```
collision entropy H_2(H_r(M)) = -log2(sum_y Pr[H_r(M)=y]^2) > 29 bits.
```

This is a sampling-confidence statement about a fixed population, not a
deterministic theorem about the unknown probability. It gives the SAME
29-bit statistical floor at all eight depths because the same sample size
and pass event are used. It does not estimate a security increment per round.

The design initially declared the weaker ceiling 2^-26. During analysis we
derived the sharper universal inequality below, giving 2^-29 from exactly
the SAME pass event and preserved sample. The sharper threshold was not
predeclared. Its validity follows from a fresh, distribution-free false-pass
bound; it does not rely on another test, new samples, or a favorable choice
among empirical estimates.

### Proof of the sampling-confidence statement

Let Y have any finite discrete distribution p_j, and C=sum_j p_j^2. Let A_N
be the event that N independent observations of Y have no repeated value.
Poissonize the number of observations: take K distributed as Poisson(lambda),
independent of the observations. Bucket counts are then independent
Poisson(lambda*p_j), so

```
Pr[A_K] = product_j exp(-lambda*p_j)*(1+lambda*p_j).
```

Put `h(x)=x-log(1+x)` and `t=lambda*sqrt(C)`. Each x_j=lambda*p_j is at most
t, and sum_j x_j^2=t^2. The identity

```
h(x)/x^2 = integral_0^1 v/(1+x*v) dv
```

shows that h(x)/x^2 decreases with x. Therefore sum_j h(x_j)>=h(t), giving

```
Pr[A_K] <= (1+t)*exp(-t).
```

The no-repeat probability decreases with the number of observations, hence

```
Pr[A_K] >= Pr[K<=N]*Pr[A_N].
```

Choose N=2^18 and lambda=15*N/16. Since a Poisson variable has variance
lambda, Chebyshev's inequality gives

```
Pr[K>N] <= lambda/(N-lambda)^2 = 240/N.
```

If C>=2^-29, then `t>=15/sqrt(2)>10`. The function `(1+t)*exp(-t)` decreases
for positive t, so

```
Pr[A_N | fixed distribution with C>=2^-29]
 < 11*exp(-10)/(1-240/N).
```

Apply a union bound over the eight fixed depth functions. They may use the
SAME sample and their outputs need not be independent across rounds. The
probability that any false population assertion passes the test is less than

```
88*exp(-10)/(1-240/262144) < 0.003999 < 0.01.
```

The last inequality is checked using exact rationals: exp(10) is bounded
below by `sum_(k=0)^40 10^k/k!`. The resulting rigorous rational false-pass
upper bound is saved in `collision_results.json`; its decimal display is
approximately **0.003998854880085783**. No ideal-random-hash assumption is
used in this lemma. Only the independent-uniform input sampling model and
deterministic evaluation of the fixed hash variants are needed.

### What work bound follows, and what does not

On the asserted population property, a search consisting of q independent
uniform H159 message queries and comparisons of their digests satisfies

```
Pr[at least one genuine full-digest collision] <= binomial(q,2)*2^-29.
```

For example, q=2^14 gives a ceiling below one quarter. At least **23,171**
queries are necessary for this upper bound to permit 50% success. This is
only a modest lower bound for this particular random-sampling strategy,
subject to the statistical confidence above. It is not a work lower bound
for arbitrary algorithms, chosen messages, differential attacks, or an
adversary using a special algebraic construction. It is particularly not
29-bit collision resistance.

## Interpretation and limits

The experiments found real truncated collisions and checked whether those
same pairs extend to eight rounds. They established an exact finite-family
injectivity result and a new distribution-free statistical bound for
random-message collisions over the entire H159 population.

They did not find a structural full-digest collision attack. This pass used
enumeration, sorting, exact arithmetic, and source replays; it did not solve
the full 256-bit collision equations with SAT or MILP. Absence of a collision
in about a million messages is entirely unsurprising for an ideal 256-bit
hash, so it cannot certify the generic 128-bit collision-work target.

The nearly similar short-prefix counts at different depths also cannot
validate the hypothetical growth curves in `ESTIMATION.md`. Stronger
per-round attack-work estimates require concrete structural attacks and
their extensions, or proofs covering those attack classes. The 29-bit
collision-entropy floor here is a different, precisely defined quantity.

## Independent verification and preserved evidence

- All **10,485,760** round-boundary digests
  were regenerated by Clang; both complete archive SHA-256 hashes match GCC.
- Independent NumPy sorting reproduced all **80** C count rows and the exact
  complete lists of 32-bit and 40-bit candidate pairs.
- All **2,118** candidate input messages
  were replayed with both original scalar and AVX2 APIs at every depth:
  **16,944** full-state comparisons passed.
- Candidate eight-round digests also match both original full hash APIs.
- Collector controls separately compare indexed checkpoints with original
  scalar and AVX2 prefix APIs on regularly spaced inputs.
- The initial source hashes and the preserved random-sample hash all match.
